# Explicit webcam presentations (source implementation)

Pi registers **`present_to_webcam`** independently of `/talk` voice or FaceTime. It may autonomously show intended public content in **this Pi session's already opted-in, ready webcam/HUD publisher**, including while Talk is inactive or FaceTime is in standby. It never enables sharing or launches an app. Registration and `session_start` start no resources. Execution checks the invocation's session against private actual publisher ownership and the current Pi session, not event-bus Talk status. Missing authority APIs on older injected bridges fail closed. Errors distinguish **Webcam sharing is off**, **different Pi session**, and **publisher unavailable** without exposing private IDs.

**`present_to_call` remains a separate, backward-compatible strict-call API.** It still requires an owned, verified connected FaceTime call, current voice readiness/audio gate and active publisher; its panel ends with that call. Do not use it without a verified call. Both tools share one replacement slot/controller/private image cache: either tool explicitly replaces or clears the panel, but failed call authorization does not clear a standalone webcam panel. Neither grants call, app-launch, audio, provider or camera-activation permission. Captions remain independently call-scoped.

Examples (tool arguments, not slash commands):

```json
{"action":"show","title":"Next steps","text":"1. Review the patch\n2. Approve deployment separately"}
{"action":"show","imagePath":"/absolute/canonical/path/diagram.png","text":"The queue is bounded."}
{"action":"clear"}
```

`show` fully replaces the previous panel; `clear` accepts no content fields. Text is plain visible text, not HTML/Markdown execution. Maximum: 1,200 characters / 2,400 UTF-8 bytes, 16 lines, eight paragraphs; title is one line / 96 UTF-8 bytes. Short text is preferable: overflow shows an ellipsis, never scrolling. Images aspect-fit without cropping. PNG/JPEG only, regular absolute local files without symlink components, 24 bytes–8 MiB, at most 4096 pixels per edge / 8,388,608 pixels. Known credential paths, controls, obvious auth patterns and hidden-reasoning tags are rejected. This is **not a general secret detector**: choose only intended public camera content. Sources are never overwritten or deleted.

## Visibility and lifetime

Both editor preview and hidden output use the same main-owned current presentation via the shared scene. Render order is world → existing HUD → presentation → CC. Only intersecting HUD meshes (also those inside the bottom 120px CC band) are masked for that render pass; exact prior visibility is restored in `finally`. HUD updates, Activity transcript, natural-height Todos/subagents, animations and saved settings continue unchanged. Portrait/landscape and padding use actual current HUD bounds. Captions remain last, with a reserved 120px bottom band while presenting.

**Off HUD and HUD opacity do not suppress an explicit presentation or CC.** Clear with `present_to_webcam {"action":"clear"}` or turn off webcam sharing. No visibility preference was added. A standalone panel persists across Pi turns, agent completion, voice stop, call end and FaceTime standby. It clears on explicit replace/clear, branch/session change, sharing/publisher stop, disconnect/stale, endpoint retarget, demo transition or app quit. The legacy call tool's panel additionally clears on call/ownership/audio-gate loss or voice stop. Caption lifecycle is unchanged. Main invalidates pending work immediately; old revisions and late preparation/image-load promises cannot revive cleared pixels. Returning from demo/disconnect requires a fresh presentation, not history replay.

A ready publisher may store a panel before any renderer connects. Successful webcam execution reports **“Presentation published to active webcam feed”**, not that anyone sees it or that a call exists. Actual camera output/consumers are independent prerequisites. Closing the editor window merely hides it; quitting/disconnecting the app clears the panel.

## Renderer style and transitions

The presentation now shares `avatar/hud-panel.ts` with the existing telemetry HUD: the same cyan chamfered frame, dark blue/teal gradient glass, restrained edge glow, amber rules and monospaced type. There is no generic PRESENTATION/metadata label. Optional titles wrap above an amber-accented divider; body text preserves paragraphs and hanging bullet/numbered-list indents, with an ellipsis for overflow. Title/body sizes stay at 26/24 logical pixels in either orientation. Images aspect-fit inside a matching chamfered glass well, never stretch or crop. The larger center/right landscape card and portrait card both end above the bottom 120px caption band.

Opening reuses the HUD's **1.08s line → perimeter trace → glass → content scan** shader; closing reverses from the current phase over **0.62s**. Rapid show/clear/show reverses the same frame rather than allocating/resetting one. Replacement keeps its frame and bounds, discards old ink immediately, and softly scans/fades new content in over **0.28s**; decoded images fade over **0.24s** without moving text. No outgoing-content crossfade/history is retained. Explicit clear, stale/disconnect and scope/run loss erase text/image pixels and cancel image loads synchronously; only the empty, non-sensitive frame animates out. Render-only overlap/CC masking remains active throughout that exit, restoring exact configured visibility on every pass as before.

Two reusable fixed backing canvases/textures/quads separate glass from protected content. Animation changes only uniforms/visibility; changed content is coalesced to at most 30 paints/second (security erasure is immediate), and layout/glass repaints only on orientation changes. Late image callbacks remain generation-fenced. Resources are disposed with the overlay. `scene.ts` only advances the renderer animation; authority, feeds, preload/main, tool registration, CC rendering and Talk/call lifetime are unchanged. These are **source-only renderer/HMR changes, untested and unbuilt**; no live content was published or captured for this styling pass.

## Image and transport boundary

The producer copies only the selected image into `join(dirname(actualHudSocket), 'presentations', opaqueId + '.png|.jpg')`. Custom agent/socket directories therefore relocate producer and consumer together. Webcam and presentation directories must be owned/private 0700, files 0600; source/cache symlinks are refused. Cache retains at most current + staging (16 MiB per controller), including failed-cleanup ownership records. Replace/clear/end removes only exact module-owned inode entries. No scan, recursive sweep, arbitrary file selector, HTTP server, remote URL or renderer Node access is added.

Periodic HUD snapshots remain metadata-only and ≤128 KiB, with exact nested allowlists. The outer HUD stays version 1. Legacy presentation `{version:1, scopeId, runId, id, ...content}` retains all connected-call/run checks. New webcam presentation `{version:2, scopeId, id, ...content}` has **no voice runId** and must match the snapshot's separate optional `displayScopeId`. That opaque publisher generation rotates on start/session/branch/disconnect; renderer/main fences additionally bind socket/stream/session/branch and revision. Only v2 panels add `displayScopeId` to frames; legacy/no-panel frames retain their existing shape. New validators accept old call-scoped frames; older exact validators reject v2 panels rather than weakening validation. Original paths, source names, private session/call identities and image bytes never enter that wire. Main derives the cache filename from opaque validated metadata and its **actual** current socket, checks directory/file ownership and bytes again, decodes with Electron, and downsizes/re-encodes to ≤1600px longest edge / ≤2 MiB. A dedicated `presentation:state` event and no-argument `presentation:get` getter serve only the existing allowlisted editor/output main frames. There is no renderer-to-main load-image API. Subscribe-before-get plus generation fences protects initial state, replacements and clears. Failed image decoding leaves new text/a neutral placeholder, never previous pixels.

The custom tool renderer/result does not echo paths or contents into terminal/HUD fallbacks. Pi's own internal session log can still retain raw tool arguments; presentation does not rewrite that storage. Existing consented Activity conversation/compact previews remain independent and can themselves contain sensitive public text.

## Limits and loading later

Unix same-user local filesystem required. Directory descriptor/inode checks reject symlinks and replacements, but portable Node lacks race-atomic `openat`/`unlinkat`: trusted ancestor owners/same-UID processes must not maliciously race renames. Native codecs are bounded by input dimensions/bytes, not an OS memory sandbox. Normal cleanup is display-scoped (call-scoped for the legacy tool); abrupt kill/power loss can leave private orphan files, with no global cross-crash/process quota or sweeper. Camera activation/publishing and real FaceTime video availability remain separate prerequisites; showing a panel does not enable any of them.

**Source-only, explicitly untested/unbuilt.** No tests, checks, compilers, builds/rebuilds, app launches/restarts, calls or probes were executed. Test sources are not passing evidence. Later, with authorization: Pi **`/reload`** exposes `present_to_webcam`; explicitly re-enable sharing after reload closes the old publisher. An already running/packaged Electron needs updated JS/main/validator bundles and a **full restart**; renderer HMR alone cannot load these changes. If running from a prebuilt app, a later explicitly authorized rebuild/package is needed to incorporate source edits; no build is needed merely to load Pi's tool. Existing preload/IPC names remain compatible and unchanged. The current session's already-exposed `present_to_call` tool remains strict until reload as well. No Swift/native rebuild is required. Electron decoding/IPC, both orientations, cleanup races and end-to-end video still need authorized validation.
